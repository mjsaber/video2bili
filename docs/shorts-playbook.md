# Shorts 方法論（2026-09-14 沉澱）

長片之外的第二條產品線。目標不是 Shorts 本身的播放，而是把推薦來的新觀眾帶到長片和訂閱。
證據檔：`assets/analytics/2026-09-13_bg_shorts_research.{json,md}`；首條實例 `output/shorts_2026-09/QlJ7_2hp_demon_short.md`（v1→v6 全部改版原因）。

## 1. 市場事實（做決策時引用，不要憑感覺）

| 事實 | 數據 | 用法 |
|---|---|---|
| 頭部形態 | Shadybunny 20–44 萬/支、JeefHS 20 萬：頂尖主播單一回合或單場戰鬥、主播原聲、標題一句斷言 | 一條只證明一件事 |
| 時長 | ≥1 萬播放 148 支中位 70 秒；90–119 秒桶播放中位最高（124K），30–59 秒最弱（64K） | 45–135 秒都可，不追求最短 |
| 版式 | 1080×1920：上約 60% 放大的棋盤裁切，下約 40% 主播臉 | 棋盤要讓手機看得清隨從數值 |
| 開頭 3 秒 | 棋盤上大標題 + 指向關鍵隨從的箭頭 + 主播當時那句話；3 秒後全部消失 | 不做獨立片頭卡 |
| 中文區 | 沒有頭部樣本（最高 3 萬，吐槽向）；「英雄戰場」標籤下一半是 Roblox 同名遊戲 | 這是未驗證市場；標籤必帶 #爐石戰記 |
| 可點入口 | Shorts 不支援片尾元素/資訊卡；簡介連結在播放頁不能點；留言裡的連結可點；播放器左下角有原生訂閱鈕 | 連結靠留言，訂閱靠指向原生鈕 |

## 2. 選段：弹幕密度找回合，抽幀定邊界

1. 只拉彈幕不拉影片：`yt-dlp --cookies-from-browser chrome --skip-download --write-subs --sub-langs danmaku`，對候選長片的每個來源都拉。
2. 90 秒滑動窗口（步長 5 秒）計數，去掉開頭 60 秒和結尾 45 秒。輸出每個來源前三個峰值 + 樣例彈幕。
3. **讀峰值窗口的全部彈幕**再決定。峰值有三種：高光（要啥來啥、破萬、吃雞）、教學（「學到了」）、互怼（「學不會」「這對嗎」）。三種都能做，但斷言寫法不同。
4. 抽幀定回合邊界：從峰值往前找「招募階段開始」（計時器重置、Recruit 橫幅），往後找戰鬥結束或結算彈窗。用 `--range` 拼：招募 ~ 戰鬥結束 + 結算彈窗，跳過中間的新局選牌畫面。
5. 歸檔裡的 `*_danmaku.json` 只有 ~100 條抽樣，不能用來算密度。

## 3. 產出：`video2yt-short`

```bash
uv run video2yt-short --video "temp/<dir>/<bv>.mp4" \
  --range 19:48~21:57 --range 22:02~1324.3 \
  --claim "只剩2血\n惡魔破萬" --comp 自傷惡魔 --rank 這局第1名 \
  --context "第14回合・英雄剩2血・場上300攻" --promise "90秒後全場破萬 最後第1名" \
  --stage 招募中@19:48 --stage 開戰@21:22 --stage 結算@22:02 \
  --srt lines.srt --board 460:90:1020:860 --face 1490:720:410:280 \
  -o output/shorts_<yyyy-mm>/<slug>_v1/<slug>.mp4
```

- **來源**：原始 `<bv>.mp4` + 同目錄 `<bv>.danmaku.xml`（工具自動讀取，按棋盤面板重新排版並下移避開角標）。不要用燒好彈幕的成片。
- **棋盤框**：每個主播的直播版面不同，先抽一幀量。郭楓荷 `460:90:1020:860`；預設 `600:120:1060:880` 只適用全幅遊戲畫面。
- **臉框**：抽一幀量。來源自帶橫幅（瓦莉拉「小助理」「抖音/微博/B站」條在 y 760–825）不要裁掉臉去躲它：把臉框從橫幅上方起（瓦莉拉 `1470:790:450:290`），再用 `--caption-band 150` 蓋一條純黑，主播原話字幕就放在黑條裡（使用者 2026-09-15 決定）。郭楓荷無橫幅：`1490:720:410:280`。頭部樣本全是真人臉；沒有臉才用女老板。
- **文字四層**：斷言（≤12 字/行 ×2）、語境行（回合/血量/場面，≤20 字）、預期行（幾秒後看到什麼，≤20 字）三者 0–3 秒滑入；階段標籤（招募中→開戰→結算，≤6 字）左上角全程。
- **主播原話**：從原始 ASR 挑 4–6 句轉繁體，只挑有情緒或有決策的句子；術語未核驗的句子不用。字幕放主播畫面頂部，前 3 秒讓位給斷言。
- **片尾 4 秒**：「點左下角「訂閱」」+ 指向左下角的浮動箭頭 + 「完整影片：看簡介置頂連結」；女老板抬到底部 400px 遮擋區之上。
- **音訊**：**必須用 song-remover 分離後的 `<bv>/no_music.wav`（人聲+遊戲音效，只去音樂）**，沒有才退到 `speech.wav`（先跑 `video2yt-stems`，工具自動讀取同名目錄），不能用來源混音。教訓：dZFbEQ0k-zk（2026-09-15）用原混音，直播 BGM「Selfish」被 Content ID 命中，Short 全球封鎖（Shorts 對受版權保護音樂的容忍長度極短，長片只是不能營利，Short 是直接不能播）。no_music.wav 保留遊戲音效。**再加長片同一套替換 BGM 床**：先 `video2yt-music-mix <bv>.mp4` 生成 `<bv>.music_bed.wav`，工具自動讀取並按 burn.py 的配方混入（音量 0.12、sidechain 壓在人聲之下、開頭 1 秒淡入），並把 `<bv>.music_credits.txt` 複製成 `<輸出>_music_credits.txt`——**這些署名行必須貼進簡介**（CC BY）。`--no-bed` 關閉。理由：去掉 BGM 後主播沒說話的段落會整段靜音（龍蝦 Short 有 40 秒），使用者 2026-09-15 決定按長片加法加 BGM。

## 4. 發布

1. `youtube_metadata.json`：標題 = 斷言句 + `｜爐石戰記 英雄戰場 #Shorts`；tags 含四個固定詞；簡介第一行長片連結、來源署名、`#爐石戰記 #英雄戰場 #Shorts`。上傳工具會做關鍵字檢查。
2. 上傳後立刻 `scripts/post_comment.py` 發連結留言（範本 `output/shorts_2026-09/short_link_comment.txt`）。
3. 播放列表：帶 `#Shorts` 的標題只進「英雄戰場 S{season} Shorts」（`playlists.classify` 已處理），不進長片列表。
4. 兩步 API 做不到、用 Claude-in-Chrome 做（使用者 2026-09-15 指定）：
   - **置頂留言**：`youtube.com/watch?v=<id>` → 往下捲到留言 → 自己那則的「Action menu」→ Pin → 對話框再按 Pin（ref 點擊常不生效，改用座標點）→ 用 find 確認出現「Pinned by」。
   - **相關影片**：`studio.youtube.com/video/<id>/edit` → 右側「Related video」卡的鉛筆 → 對話框選對應長片（可用搜尋框）→ Save → 確認 Save 鍵變灰。
4. **不要反覆刪舊傳新**：每次替換清零數據，短時間重複上傳同標題可能降推薦。改版攢到下一條。

## 5. 驗證

7 天看兩個數：Shorts 觀看完成率；長片流量來源裡「來自 Shorts」占比。任一為零就停止這條線。結果記入該長片的 `growth_plan.md`。

## 6. 每期固定流程（使用者 2026-09-16：每個素材都要同時做一條 Short，同時上傳並引流）

長片的每個來源素材各切一條，和長片同一天發。素材已經跑過 fetch / stems / ASR，Short 只多兩步（music-mix + 切片）。

1. `video2yt-music-mix temp/<dir>/<bv>.mp4`（長片本來就要跑；Short 自動讀同名 bed）。
2. 選段：該來源彈幕 90 秒滑窗最高峰 → 讀全部彈幕 → 抽幀定回合邊界（§2）。
3. `video2yt-short`：主播固定框（郭楓荷 / 瓦莉拉見 memory `feedback_shorts_streamer_layouts`；新主播先量框並記錄），斷言 + 語境 + 預期 + 階段標籤 + 4–7 句原話字幕。
4. 預覽抽幀核對：第 1 秒、開戰、結算、片尾；音量三段。
5. `youtube_metadata.json`（標題斷言句 + `｜<流派> 爐石戰記 英雄戰場 #Shorts`，簡介第一行長片連結 + 音樂署名）→ `video2yt-upload`（自動進 Shorts 列表、關鍵字檢查）。
6. `scripts/post_comment.py` 發長片連結留言 → Chrome 置頂 → Chrome 設「相關影片」指向長片（§4）。
7. 上傳後 1 小時內用 API 查 `regionRestriction`，確認沒被 Content ID 封鎖。
8. `growth_plan.md` 記錄：Short ID、長片 ID、選段依據（峰值窗口 + 彈幕類型）、留言 ID、置頂/相關影片完成時間。7 天後補完成率與長片「來自 Shorts」占比。
