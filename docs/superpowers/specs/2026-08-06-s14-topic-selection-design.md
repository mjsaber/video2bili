# S14 新版本选题筛选设计

**日期：** 2026-08-06  
**状态：** 对话设计已批准，等待书面规格确认

## 目标

从近期《炉石战记：英雄战场》视频中找出一个适合频道下一期制作的 S14 新版本选题。候选必须能由至少两位白名单主播的实战素材共同支撑，并优先体现 S14 新卡、新机制或由新版本形成的新流派。

## 扫描范围

- 首轮使用 `video2yt-topic` 的 7 天窗口，覆盖 S14 创作者抢先体验至正式上线后的最新素材。
- 使用仓库现有主播白名单、已完成题材清单和历史项目 intro 自动去重。
- 保留默认的对战时长下限、弹幕采样量和每位主播抓取页数。
- 若首轮得到的合格 S14 新题少于 3 个，再围绕首轮出现的 S14 新卡与流派别称进行定向补搜；不直接把窗口扩至 14 天，以免 S13 对局污染结果。

## 排序标准

候选按以下顺序评估：

1. 两位或以上不同主播展示同一流派、核心卡或新机制。
2. 内容明确属于 S14，而不是标题含“新赛季”的旧 S13 对局。
3. 能说明具体机制、运营节点或成型路径，适合做“完整教学”。
4. 有清晰的战力兑现、极限数据或决赛反转，可用于冷开场和缩略图。
5. 未出现在 `assets/topic/done_topics.txt`，也不是已发布内容的同义题材。

## 输出要求

- 直接转发 `video2yt-topic` 在 `===== CHAT-READY REPORT =====` 标记之间生成的完整报告，不自行改写为缺少链接的摘要。
- 每个候选在聊天中必须显示所有对应主播的 `https://www.bilibili.com/video/<BVID>` 链接，包括不推荐的候选。
- 在原报告之上补充 S14 归属、已做题材同义词和推荐顺序，不删除原始字段。
- 明确给出一个首选题材，并说明它相对其他候选的版本新鲜度、双素材互补性和成片卖点。
- 报告同时保存在 `output/topics/2026-08-06.md`。

## 失败与降级处理

- Bilibili cookie 或风控失败时，先报告实际错误，不伪造候选；再按 CLI 支持的登录浏览器 cookie 路径重试。
- Codex 汇总超时时保留已抓取数据并重试汇总，不以标题猜测机制。
- 若首轮不足 3 个合格候选，执行定向补搜；若补搜后仍不足，明确报告实际数量，不用 S13 素材凑数。

## 完成标准

- 生成并保存当日完整报告。
- 每个可见候选都带完整 Bilibili 来源链接。
- 首选题材有至少两位主播的可用实战来源。
- 首选题材已与 done topics 和已发布视频交叉核对。
- 首选题材的 S14 新版本依据可由视频内容或可靠版本资料验证。
