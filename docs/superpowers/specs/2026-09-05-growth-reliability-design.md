# 视频拉新与发布可靠性设计

2026-09-05：用户采纳仓库审阅中的全部建议并授权修复。范围为代码、工具和未来制作默认流程；既有视频的线上 A/B 实验需要在 Studio 单独执行，测试过程不发布视频。

## 数据与恢复

每个项目保存 publication.json，包含 channel_id、video_id、uploaded_at、视频完整 SHA-256、上传元数据 SHA-256、封面与播放列表状态。先落盘 uploading，获得远端 ID 后立即保存 uploaded，后续步骤全部完成才保存 complete。重跑复用 ID；无 ID 的中断状态必须先核对 Studio，再显式 adopt 或 retry-uncertain。进程锁防止并发重复上传或清理。

清理仅接受 complete 回执，按回执中的上传时间排序，执行前重新验证全部目标并加锁。先归档所有项目，再删除大文件；归档失败则不删除。assets/publications/<video_id>/ 永久保留顶层文稿、图片、元数据、实验记录；uploaded_thumbnail 文件只接受与成功上传哈希一致的图片。旧项目不会仅凭元数据自动获得清理资格。

## 内容与包装

新观众版开场试验先展示真实结果，再说明观看收益；5 秒结果画面、15–20 秒内进入关键操作是起始假设，最终以留存数据检验。机制讲解移动到对应操作；关键决策章节与实际剪辑片段独立。一个短开场加一场实战可以合并，章节不满足平台条件时省略章节而不阻止视频输出。

封面保留品牌默认，也支持收益优先布局、文本自动适配、可选 Logo/吉祥物。变体保存标题、假设、图片哈希、制作时间和待 Studio 实验状态，配移动端预览。CTA 在首次展示有用决策后短暂覆盖实战画面，不默认等到第一场结束；片尾在 Studio 配置具体下一条视频。

## 选题与测量

选题使用每小时播放及同一主播候选中位数校正，披露样本数和缺失基线。模型提取的证据、置信度、补丁版本不是事实验证；未知字段允许空值，所有候选保留人工待核验状态。全源抓取失败不产出正常空报告，部分失败显式披露。原始候选、弹幕和未配对来源也写入 JSON 供复核。

复盘保存 24h/7d/28d 检查点、实际测量区间、采集时间和流量来源。只读 Analytics 采集与上传授权隔离；CTR、曝光、新观众和精确 30 秒留存可从 Studio 导入，不以公开播放数推测。按日桶的 API 报告不能冒充发布后精确 24 小时结果；不足的观察不宣布胜出。

## 验证

每个行为先加入复现测试再实现；完整 pytest、真实 ffmpeg 短片段验证、真实封面缩略预览和独立代码审阅。所有验证素材使用测试临时目录，保留工作区原有修改。
